## ❓Java Collections Framework
자바에서 자료구조를 표준화해서 제공하는 라이브러리로 List, Set, Map 인터페이스와 그 구현체들로 구성되어 있습니다.

**➕ Map 인터페이스 구현체의 종류** </br>
- **HashMap** : 해시 테이블 기반 데이터 저장, 비동기적으로 동작하고 멀티 스레드 환경에서 안전하지 않음 -> 단일 스레드에서 빠른 성능이 필요할 때 사용, 순서 보장 X
- **HashTable** : 해시 테이블 기반, 전체 동기화 처리로 멀티 스레드 안전하지만 전체 테이블에 락을 걸기 때문에 병렬 성능이 떨어짐
- **ConcurrentHashMap** : 특정 버킷 단위로 락을 걸어 동시성이 중요한 멀티 스레드 환경에 HashTable의 성능 문제 개선
- **LinkedHashMap** : HashMap 모든 기능 포함 + 데이터 삽입 순서 유지
- **TreeMap** : 이진 탐색 트리 기반, 키 자동 정렬, 특정 범위 키 검색이나 최소/최대 값 조회에 유리, HashMap에 비해 삽입/삭제/검색은 느림 O(logn)

**➕ Set 인터페이스 구현체의 종류** </br>
- **HashSet** : 해시 테이블 기반, 순서 보장/중복 허용 X, 삽입/삭제/검색이 평균 O(1)로 매우 빠름
- **LinkedHashSet** : HashSet 모든 기능 포함 + 데이터 삽입 순서 유지
- **TreeSet** : Red-Black 트리 기반 이진 탐색 트리 사용, 데이터 자동 정렬

**➕ List 인터페이스 구현체의 종류** </br>
- **ArrayList** : 배열 기반, 크기 동적으로 조절, 인덱스 접근 O(1), 중간에 삽입/삭제 시 요소들 이동으로 느림
- **LinkedList** : 연결 리스트 기반, 삽입/삭제는 빠르지만 특정 인덱스 접근은 순차 탐색이라 느림, Queue 구현체로 자주 사용
- **Vector** : ArrayList처럼 동적 배열 기반이지만 동기화 처리로 멀티스레드 환경에 안전

</br>

## ❓Lambda란?
람다는 익명 함수를 간결하게 표현하는 문법이며 자바에서 함수를 하나의 값처럼 전달할 수 있도록 해주는 기능입니다.
함수형 인터페이스를 기반으로 동작하기에 추상메서드가 하나인 인터페이스를 구현하는 방식입니다.

**➕ 함수형 인터페이스에 추상 메서드가 하나인 이유** </br>
함수형 인터페이스는 람다식을 담기 위한 인터페이스입니다. </br>
람다식은 하나의 동작(하나의 함수)을 표현하는 문법이기 때문에 인터페이스에 추상 메서드가 하나만 존재해야 어떤 메서드를 구현하는지 명확해집니다. 즉, 람다식은 어떤 "동작"을 추상화한 인터페이스의 구현체가 되는 거고 그 인터페이스가 바로 함수형 인터페이스이다.

</br>

## ❓Stream이란?
자바 8에서 도입된 API로, 컬렉션이나 배열의 데이터를 함수형 스타일로 처리할 수 있도록 해주는 기술입니다.
람다와 함수형 인터페이스를 기반으로 동작하고, 데이터를 선언형 방식으로 필터링, 변환, 집계할 수 있게 해줍니다.

**➕ Stream과 for-loop의 성능 차이를 설명해 주세요.** </br>
일반적인 단순 반복에서는 for-loop가 더 빠를 수 있습니다. Stream은 내부적으로 람다와 함수형 인터페이스를 사용하기 때문에 약간의 오버헤드가 발생합니다. </br>
하지만 데이터 처리 로직이 복잡하거나 가독성과 유지보수가 중요한 경우에는 Stream이 더 적합합니다.

**➕ Stream은 병렬 처리가 가능한가요?** </br>
네 가능합니다. parallelStream() 또는 stream().parallel()을 사용하면 개발자가 직접 스레드를 생성하지 않아도 ForkJoinPool을 사용해 자동으로 병렬 처리됩니다. </br>
내부적으로 Fork/Join Framework를 기반으로 작업을 분할(Fork)하고, 결과를 합치는(Join) 방식으로 동작합니다.
또한 Work-stealing 방식으로 동작하기 때문에 한 스레드의 작업이 부족하면 다른 스레드의 작업을 가져와 처리합니다.  </br>
하지만 데이터가 적거나 공유 자원이 많으면 오히려 병렬 처리 오버헤드로 인해 성능이 떨어질 수 있기 때문에, CPU 코어가 많고 연산량이 많은 경우에 병렬 스트림이 효과적입니다.

**➕ Stream에서 사용하는 주요 함수형 인터페이스를 설명해 주세요.** </br>
Stream은 java.util.function 패키지의 함수형 인터페이스를 사용합니다. 대표적으로 아래와 같습니다.
- Predicate<T> → filter()
- Function<T, R> → map()
- Consumer<T> → forEach()
- Supplier<T> → generate()
- BinaryOperator<T> → reduce()

**➕ Stream에서 외부 변수를 사용할 때 final이어야 하는 이유는 무엇인가요?** </br>
람다에서 외부 지역 변수를 사용할 경우 해당 변수는 effectively final 이여야 합니다. 람다가 실행되는 시점에 외부 변수 값이 변경되면 동기화 문제가 발생할 수 있게 때문입니다. 자바 8부터는 명시적으로 final을 붙이지 않아도 값이 변경되지 않으면 effectively final로 간주되어 사용할 수 있습니다. 

</br>

## ❓optional 생성 방법
Optional은 자바 8에서 도입된 클래스로, 값이 있을 수도 없을 수도 있음을 명시적으로 표현하기 위한 컨테이너 객체입니다.
null을 직접 방환하는 대신 Optional을 사용하여 NullPointerException을 줄이고, 값의 존재 여부를 확실히 표현할 수 있습니다. 
- **Optional.of(T value)** : null이 아닌 값으로 Optional을 생성할 때 사용, null이면 NullPointerException, 즉 값이 반드시 존재해야 한다는 것을 보장
- **Optional.ofNullable(T value)** : 값이 null일 수도 있을 때 사용, null이면 자동으로 빈 Optinal로 변환
- **Optional.empty()** : 값이 없는 빈 Optional을 생성

</br>

## ❓map과 flatMap 차이를 설명해 주세요.
map과 flatMap은 Stream이나 Optional처럼 컨테이너 내부의 값을 변환할 때 사용하는 연산입니다. 두 연산 모두 입력값을 가공해서 새로운 값을 반환하고, 원본 데이터는 변경되지 않습니다.
- **map** : 각 요소를 하나의 다른 값으로 변환할 때 사용합니다. 즉 1:1 변환입니다.
- **flatMap** : 변환 결과가 또 다른 Stream이나 Optional처럼 중첩된 구조일 때 이를 평탄화해주는 연산입니다.
