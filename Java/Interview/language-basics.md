## ❓java의 final 키워드 (final/finally/finalize)
모두 같은 final이 들어가지만 다른 용도로 사용됩니다.
- final : 변수, 메서드, 클래스에 사용될 수 있는 제어자이고, 변수에 사용되면 값이 변경될 수 없고 메서드에 사용되면 오버라이딩될 수 없고 클래스에 사용되면 상속할 수 없게 됩니다.
- finally : try-catch 블록에서 사용되는 예약어이고, try블록에서 에외가 발생하느냐와 관계없이 항상 실행되는 코드 블록입니다.
- finalize : 객체가 가비지 컬렉터에 의해 메모리에서 제거되기 직전에 JVM이 마지막으로 호출해주는 메서드입니다.

</br>

## ❓== 와 Equals() 메서드의 차이는?
자바에서 == 연산자는 두 참조 변수가 같은 객체를 참조하는지 즉, 메모리 주소가 같은지를 비교하고 </br>
equals() 메서드는 객체의 내용이 같은지를 비교합니다.

**➕ 그럼 equals()는 모든 객체에서 값 비교를 하나요?** </br>
아니요. equals()는 Object 클래스에서 상속되며 Object의 기본 구현은 ==와 동일하게 참조 동일성을 비교합니다.
그래서 String, Integer처럼 값 비교가 필요한 클래스만 equals()를 오버라이딩하여 실제 값을 비교합니다.
예를 들어, new 를 이용해 string 객체를 두번 생성하고 equals()로 비교하면 다른 메모리에 할당되어 false가 나올것 같지만 true가 나옵니다.

**➕ 기본형(primitive) 타입에서는 어떻게 비교하나요?** </br>
int, double 같은 기본형 타입은 객체가 아니라 값 자체를 저장하므로 == 연산자가 곧 값 비교입니다. 
기본형에는 메서드가 없기 때문에 equals()는 사용할 수 없습니다.

</br>

## ❓equals(), hashcode() 설명해보세요.
equals()와 hashcode() 모두 자바의 부모 객체인 Object 클래스에 정의되어 있어서 자바의 모든 객체가 상속받습니다.
- equals()는 2개의 객체가 동일한지 검사하기 위해 사용하는데, 2개의 객체가 가리키는 곳에 동일한 메모리 주소일 경우 동일하다고 합니다. (즉 내부적으로 위의 == 를 구현하는 것)
- hashcode()는 실행 중 객체의 유일한 Integer 값을 반환하는데, Object 클래스에서는 객체의 메모리 주소를 반환하도록 되어있습니다.

</br>

## ❓Wrapper class
프리미티브 타입인 기본형은 값 자체를 저장하는 타입이고, 이를 감싸서 객체처럼 사용할 수 있게 만든 클래스를 래퍼클래스라고 합니다. 기본 자료형을 래퍼클래스로 변경하는 것을 Boxing이라고 하고, 반대로 래퍼클래스를 기본 자료형으로 변경하는 것을 UnBoxing이라고 합니다. 

**➕ 왜 사용할까?** </br>
- 컬렉션과 재네릭은 객체 타입만 다룰 수 있어서 기본형 대신 래퍼 클래스를 사용합니다.
- 기본형은 null을 가질 수 없지만, 래퍼클래스는 객체이기 때문에 null 표현이 가능합니다.
- 문자열을 숫자로 변환하는 Integer.parseInt() 같은 유틸리티 메서드가 래퍼클래스에 제공됩니다.

</br>

## ❓new String()과 ""의 차이에 대해 설명해주세요.
new String과 ""리터럴은 둘 다 문자열을 만들지만 객체가 생성/관리되는 방식이 다릅니다. </br>
new String()은 new 키워드를 사용하기 때문에 항상 힙 영역에 새로운 String 객체를 생성합니다. 즉, 같은 값이라도 호출할 때마다 서로 다른 객체가 만들어집니다. </br>
문자열 리터럴 ""은 String Constant Pool(문자열 상수 풀)에 저장됩니다. 이미 동일한 문자열이 존재하면 새로 만들지 않고 기존 객체를 재사용하기 때문에 같은 리터럴은 같은 객체를 참조합니다. 

</br>

## ❓java String이 불변 객체인 이유
- **보안** : String은 비밀번호, 계정 정보, 파일 경로처럼 민감한 데이터를 자주 담습니다. 불변 객체이기 때문에 참조를 공유하더라도 다른 코드에서 내용을 변경할 수 없어 보안상 안전합니다.
- **해시코드 캐싱** : String은 HashMap, HashSet의 키로 자주 사용됩니다. 값이 변하지 않기 때문에 hashCode를 한 번 계산해 캐싱할 수 있고, 값 변경으로 인한 검색 오류를 방지할 수 있습니다.
- **재사용성(String Constant Pool)** : 문자열 리터럴은 String Constant Pool에 저장되어 같은 값이면 하나의 객체를 재사용합니다. String이 가변이었다면 풀에 있는 문자열이 변경될 수 있어 재사용이 불가능했을 것입니다.
- **멀티스레드 안전성** : 여러 스레드가 동시에 같은 문자열을 참조해도 값이 변하지 않으므로 동기화 없이도 안전하게 공유할 수 있습니다.

</br>

## ❓Immutable Object(불변 객체)란?
객체가 생성된 이후 필드 값이 절대 변경되지 않는 객체를 말합니다. 값이 변하지 않기 때문에 멀티스레드 환경에서도 동기화 없이 안전합니다. 

**➕ 불변 객체를 만드는 방법** </br>
- 클래스를 final 로 선언 → 상속을 막아 하위 클래스에서 변경을 막음
- 모든 필드를 private final로 선언 → 외부 접근 및 재할당 차단
- 생성자를 통해서만 값 초기화 → Setter 제공하지 않음
- 가변 객체(List,Map 등)를 필드로 가질 경우 깊은 복사 사용 → 외부에서 참조를 통해 내부 상태가 변경되는 것을 방지
