## ❓index 가 무엇이고, 언제 사용하는지 설명해 주세요.
인덱스는 DB 테이블의 검색 속도를 높이기 위한 자료구조입니다. </br>
테이블을 Full Scan하지 않고 정렬된 구조를 통해 원하는 데이터를 빠르게 찾을 수 있도록 도와줍니다. </br>
조회(SELECT)가 많고 특정 컬럼을 조건절(WHERE)로 자주 검색할 때 사용합니다.

**➕ 인덱스의 장점과 단점은 무엇인가요?** </br>
장점 : 조회 성능 향상, ORDER BY/GROUP BY 성능 개선
단점 : 추가 저장 공간 필요(보통 테이블의 약 10%내외), INSERT/UPDATE/DELETE 시 인덱스도 함께 수정해야 해서 쓰기 성능 저하

**➕ 수정이 잦은 테이블에 인덱스를 권장하지 않는 이유는 무엇인가요?** </br>
B-Tree 기반 인덱스는
- UPDATE 시 기존 인덱스를 사용안함 처리 후 새로운 값을 추가하고
- DELETE 시 즉시 제거하지 않고 삭제 표시만 합니다.
이 과정에서 B-Tree 공간이 없으면 Page Split이 발생할 수 있고, 인덱스 재정렬 비용이 증가합니다. 즉, 쓰기 작업이 많은 테이블에서는 오히려 성능이 저하될 수도 있습니다.

**➕ 인덱스를 걸지 않은 컬럼은 어떻게 동작하나요?** </br>
인덱스가 없으면 조회 시 Full Table Scan이 발생합니다. 하지만 INSERT, UPDATE, DELETE 시 인덱스 유지 비용이 없기 때문에 쓰기 성능에는 유리합니다.

**➕ ORDER BY / GROUP BY는 인덱스와 어떤 관련이 있나요?** </br>
인덱스 기본적으로 정렬된 상태로 저장됩니다. 
ORDER BY 컬럼에 인덱스가 있으면 별도의 정렬 작업 없이 인덱스를 순서대로 스캔합니다.
GROUP BY 컬럼에 인덱스가 있으면 같은 값들이 이미 모여 있어 추가 정렬이나 임시 테이블 사용을 줄일 수 있습니다. 

**➕ 기본키는 인덱스인가요? 차이점은 무엇인가요?** </br>
기본키는 인덱스입니다. 대부분 DB에서 기본키를 생성하면 자동으로 클러스터드 인덱스가 만들어집니다. 차이점은,
- **클러스터드 인덱스(기본키)** : 리프 노드에 row 전체 존재, 중복과 Null 불가, 테이블당 1개
- **보조(논클러스터드) 인덱스** : 리프 노드에 PK 값 존재, 중복과 NULL 가능, 테이블당 여러개

## ❓Table Full Scan, Index Range Scan에 대해 설명해 주세요.
**Table Full Scan**은 테이블에 있는 모든 행을 처음부터 끝까지 읽으면서 조건을 검사하는 방식입니다. 데이터가 적거나, 대부분의 행을 조회해야 하는 경우에는 오히려 효율적일 수 있습니다. </br>
**Index Range Scan**은 인덱스의 특정 범위만 탐색해서 조건에 맞는 데이터를 찾는 방식입니다. 주로 B+Tree 인덱스를 사용하고 = ,> , <, BETWEEN, LIKE 'abc%' 같은 범위 조건에서 사용됩니다. </br>
즉, 디스크 I/O 범위가 다릅니다.

**➕ 인덱스가 있는데도 Table Full Scan이 발생하는 이유는 무엇인가요?** </br>
DB 옵티마이저가 “인덱스를 사용하는 것이 오히려 더 느리다”고 판단했기 때문입니다. 옵티마이저는 통계 정보를 기반으로 실행 계획을 결정합니다.
- 조회 비율이 높아 대부분의 데이터를 읽어야 할 때
- 인덱스 컬럼의 카디널리티가 낮을 때
- 인덱스 컬럼에 함수나 연산이 적용된 경우
