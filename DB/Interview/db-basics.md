## ❓데이터베이스 정규화에 대해서 설명해보세요.
하나의 릴레이션에 하나의 의미만 존재하도록 릴레이션을 분해하는 과정이며 데이터 일관성, 최소한의 중복, 최대한의 데이터 유연성을 위한 방법입니다.
- **1NF**(제 1정규형) : 테이블 컬럼에는 하나의 값만 → 원자성
- **2NF**(제 2정규형) : 1정규형을 만족하고, 복합키 중 일부에만 종속된 컬럼은 따로 분리 → 일부 키에만 의존하지 않도록
- **3NF**(제 3정규형) : 2정규형을 만족하고, 기본키가 아닌 컬럼이 다른 컬럼에 종속되어 있으면 분리 → 컬럼이 컬럼에 의존하지 않도록
- **BCNF**(Boyce-Codd) : 3정규형을 만족하고, 모든 결정자가 후보키가 되도록 함 → 키 아닌 컬럼이 다른걸 결정하지 않도록

**장점** : 데이터베이스 변경 시 이상 현상이 발생하는 문제를 해결하고, 구조 확장 시 변경을 최소화합니다. </br>
**단점** : 테이블을 많이 분해하면 테이블 간의 연산(Join)에서 시간이 많이 소비되어 성능 저하가 발생할 수 있습니다.

**➕ 정규화를 하지 않을 경우, 발생할 수 있는 이상현상에 대해 설명해 주세요.** </br>
1. **삽입 이상** : 불필요한 데이터가 없으면 필요한 데이터도 저장 불가 → 학생+과목 테이블에서 학생이 없으면 과목을 등록할 수 없는 경우
2. **갱신 이상** : 중복된 데이터 중 일부만 수정되어 데이터 불일치 발생 → 같은 학생의 학과 정보가 여러행에 있을 때 한 행만 수정되는 경우
3. **삭제 이상** : 불필요한 데이터를 삭제했는데 중요한 정보까지 삭제 → 어떤 학생의 마지막 과목 정보를 삭제했더니 기본 정보까지 사라지는 경우

**➕ 정규화가 무조건 좋은가요? 그렇지 않다면, 어떤 상황에서 역정규화를 하는게 좋은지 설명해 주세요.** </br>
정규화는 데이터 무결성 측면에서는 매우 좋은 선택이지만 성능 측면에서 항상 최선은 아닙니다. 
정규화가 심해지면 테이블이 많아지고, JOIN이 많아지며, 조회 성능이 떨어질 수 있습니다. </br>
**역정규화**는 성능 개선을 위해 의도적으로 중복을 허용하는 설계입니다.
- 조회가 압도적으로 많은 경우 : 메인 페이지, 통계, 대시보드처럼 읽기 위주 서비스
- JOIN 비용이 너무 큰 경우 : 항상 함께 조회되는 데이터라면 같은 테이블에 미리 저장
- 과거 데이터 보존이 중요한 경우 : 주문 테이블에 상품명과 가격을 함께 저장 → 상품 정보가 바뀌어도 과거 주문 내역은 유지 가능
